# v52.48.5.10 적용 방법

이 패키지는 `v52.48.5.9`가 적용된 프로젝트를 기준으로 합니다.

## 1. Supabase SQL 먼저 실행

Supabase 대시보드의 **SQL Editor**에서 아래 파일 전체를 실행합니다.

```text
release_v52.48.5.10/Supabase에서_실행/00_v52.48.5.10_다중층_추가동_퇴근진척.sql
```

실행 결과 맨 아래에 테이블 4개와 RPC 7개가 모두 표시되면 정상입니다.

## 2. 코드 적용

ZIP 안의 `release_v52.48.5.10` 폴더를 프로젝트 최상위 폴더에 복사합니다. 프로젝트 최상위는 `package.json`과 `src` 폴더가 보이는 위치입니다.

PowerShell에서 아래 명령을 순서대로 실행합니다.

```powershell
node .\release_v52.48.5.10\apply-v52.48.5.10-multi-scope.cjs
npm run build
git add src/page/AttendanceWorkerPortal.jsx src/page/AttendanceManagement.jsx src/utils/attendanceI18n.js src/components/AttendanceWorkAssignmentDialog.jsx src/components/AttendanceCheckoutProgressDialog.jsx src/components/AttendanceProgressFloorGrid.jsx
git status
git commit -m "v52.48.5.10 add multi-floor attendance scopes"
git push origin main
```

## 3. 배포 후 확인

- 작업자가 출근 QR 후 한 동의 여러 층 범위를 선택할 수 있는지 확인합니다.
- `선택한 세대만`을 고르면 각 층 골구도에서 작업예정 호수를 선택할 수 있는지 확인합니다.
- 퇴근 QR 후 출근 때 선택한 모든 층이 나타나는지 확인합니다.
- 퇴근 때 다른 동과 층 범위를 추가하고 완료세대를 선택할 수 있는지 확인합니다.
- 담당자 화면에서 출근 위치와 퇴근 추가 위치가 구분되는지 확인합니다.
- 승인 전에는 기존 진척관리가 바뀌지 않고, 승인 후에만 완료로 반영되는지 확인합니다.
- 반려 시 진척도는 변하지 않고 퇴근 기록은 유지되는지 확인합니다.
- Language를 바꿨을 때 새 화면 문구가 선택한 언어로 바뀌는지 확인합니다.

앱 재설치는 필요하지 않습니다. 배포 후 앱을 완전히 종료하고 다시 실행해주세요.
