v52.48.5.44.7.6.3
기성삭제 후 계약품목/공정연결 잔여자료 강제 초기화

확인된 실제 원인
- 남아 있는 계약품목 source_key가
  new-contract: / template: 형식이 아니라
  68a_1공구|경량벽체칸막이|... 같은 레거시 형식.
- 따라서 v7.6.1의 1회 자동복구 안전조건에서 제외됨.
- 이 때문에 SQL은 성공했지만 progress_contract_items가 그대로 남았고
  1) 계약품목 공정연결 화면에도 계속 표시
  2) 기성 양식 다운로드에도 이전 계약내역이 다시 들어옴

이번 수정
1. source_key 형식 조건 제거
2. 삭제/초기화 기준을 현장 + 계약버전명 + 등록회차 0건으로 통일
3. admin_reset_progress_contract_master_v2 RPC 추가
4. 기성 회차 삭제 후 메인 삭제 RPC에 이어 reset RPC를 한 번 더 호출
5. 이미 정상 삭제된 경우 already_clean으로 종료
6. 다른 등록회차가 같은 계약버전을 사용하면 skip
7. progress_contract_items를 삭제하므로 process_type 공정연결도 같이 초기화
8. 계약품목 id를 참조하는 FK 하위자료도 함께 정리

현재 이미 남아있는 테스트자료
- SQL 실행 시 orphan 후보가 정확히 1개면 자동으로 1회 정리
- 후보가 2개 이상이면 안전을 위해 아무 것도 삭제하지 않고 오류
- 실행 마지막 SELECT의 결과가 0 rows이면 현재 orphan 정리 완료

적용 후 기대상태
- 계약품목 공정연결: 잔여 품목 0
- 기성내역서작성 > 기성 양식 다운로드: 빈 최초계약 양식
