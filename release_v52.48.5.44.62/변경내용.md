# v52.48.5.44.62 변경내용

## 타입별 세대 현황 패널 우측 이동/도킹 좌표 보정

문제 원인은 Dashboard의 화면 배율이 `html { zoom: ... }` 방식으로 적용되는 반면, 패널 이동 한계와 도킹 위치가 `window.innerWidth`, `clientX`, `getBoundingClientRect()` 화면 좌표를 그대로 `position: fixed`의 `left/top` 값으로 사용한 데 있었습니다.

예를 들어 화면 90%에서는 기존 계산상 우측 끝 좌표도 다시 90% 축소되어, 실제 화면 오른쪽에 약 10% 폭의 빈 공간을 남긴 채 더 이상 이동할 수 없었습니다.

이번 버전에서는 다음을 반영합니다.

- Dashboard의 `--wooklim-dashboard-scale` 값을 읽어 화면 좌표와 레이아웃 좌표를 분리합니다.
- 우측 이동 한계를 `window.innerWidth / scale` 기준으로 계산합니다.
- 드래그 포인터 좌표도 scale로 역변환하여 실제 마우스 이동과 패널 이동을 일치시킵니다.
- `펼치기/최소화` 버튼의 `getBoundingClientRect()` 좌표를 scale로 역변환하여 패널의 오른쪽 끝이 버튼의 오른쪽 끝과 정확히 맞도록 합니다.
- 화면 크기 변경 시 수동 위치 clamp도 동일한 scale-aware 좌표계를 사용합니다.
- 위치 저장 키를 `type-summary-panel-v5`로 변경하여 이전 잘못된 v4 위치를 자동으로 끊고 기본 우측 도킹 위치부터 다시 시작합니다.

기존 공정/진척 데이터와 Supabase 구조에는 영향이 없습니다.
