# v52.48.5.44.70 변경내용

이번 오류는 프론트 화면 권한이 아니라 Supabase의 `save_expense_resolution` 내부 서버 권한 판정에서 발생한 것으로 확인했습니다.

- `public.can_access_expense_project(text)` 추가
  - 현재 시스템이 사용하는 `public.get_my_runtime_access()`의 `access_scope` / `project_names`를 기준으로 현장 접근을 판정합니다.
  - 정상 런타임 권한이 있으면 해당 결과를 최종 기준으로 사용합니다.
  - 구버전 DB처럼 런타임 RPC를 사용할 수 없을 때만 기존 `can_access_project`로 후퇴합니다.
- 기존 `save_expense_resolution`, `delete_expense_resolution` 함수의 본문 전체를 새로 작성하지 않습니다.
  - DB에 실제 설치된 함수 원문을 `pg_get_functiondef`로 읽고 `can_access_project` 호출만 지출결의서 전용 helper로 바꿉니다.
  - 따라서 기존 저장/수정/삭제 데이터 처리 로직은 그대로 유지됩니다.
- `expense_resolutions`, `expense_resolution_items` RLS 정책 중 기존 `can_access_project`를 사용하는 정책도 같은 helper로 교체합니다.
  - 목록 조회 및 수정 시 항목 조회까지 현재 런타임 현장권한과 동일하게 맞춥니다.
- SQL은 트랜잭션으로 실행합니다.
  - `save_expense_resolution`에서 예상한 legacy 권한 호출을 찾지 못하면 예외를 발생시켜 전체 적용을 롤백합니다.
