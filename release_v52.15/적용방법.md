# v52.15 적용 및 배포 방법

기준: v52.14.9가 현재 GitHub main / Vercel Production에 배포된 상태.

## 1. ZIP 압축 해제

ZIP의 `release_v52.15` 폴더가 프로젝트 최상위에 오도록 압축을 푼다.

예시 프로젝트 경로:

`C:\Users\서재형\Desktop\new`

## 2. Supabase SQL 실행

Supabase SQL Editor에서 아래 파일을 처음부터 끝까지 전체 실행한다.

`release_v52.15\Supabase에서_실행\00_v52.15_메신저_전체메시지_전송.sql`

정상 적용되면 마지막 조회 결과에 다음 함수가 표시된다.

`messenger_broadcast_text_message | p_recipient_user_ids uuid[], p_body text`

## 3. 프로그램 파일 적용

프로젝트 최상위 PowerShell에서:

```powershell
node .\release_v52.15\apply-v52.15-messenger-broadcast.cjs
```

적용 스크립트는 현재 `src/page/Messenger.jsx`가 제작 기준 v52.14.9와 일치하는지 먼저 검사한다.
다른 버전이면 기존 기능 보호를 위해 자동으로 중단한다.

적용 파일:

- 수정: `src/page/Messenger.jsx`
- 추가: `src/components/MessengerBroadcastDialog.jsx`

기존 파일은 `backup_v52.15_...` 폴더에 자동 백업된다.

## 4. 빌드

```powershell
npm run build
```

마지막에 `✓ built in ...`가 표시되는지 확인한다.

## 5. Git 상태 확인

```powershell
git status
```

## 6. 변경 파일만 정확히 추가

```powershell
git add src/page/Messenger.jsx
git add src/components/MessengerBroadcastDialog.jsx
```

`git add .`은 사용하지 않는다.
`release_v52.15`, `backup_v52.15...`, `dist`는 추가하지 않는다.

## 7. 커밋 및 push

```powershell
git commit -m "v52.15 messenger broadcast message"
git push origin main
```

## 8. Vercel 확인

운영 프로젝트 `wooklim-construction-management`에서 새 Production 배포가 `Ready`인지 확인한다.

## 9. 운영 테스트

1. 메신저 별도창을 연다.
2. 좌측 상단 `메신저` 제목 옆에서 전파 아이콘이 `+ 새 대화` 아이콘 왼쪽에 보이는지 확인한다.
3. 전파 아이콘을 클릭한다.
4. 수신자 목록이 기본 전원 체크 상태인지 확인한다.
5. `No.` 헤더 체크박스로 전체 해제/전체 선택이 되는지 확인한다.
6. 개별 사용자를 해제한 뒤 메시지를 작성한다.
7. 전송 후 선택된 사용자에게만 같은 메시지가 각각 1:1로 도착하는지 확인한다.
8. 수신자 계정에서 읽지않음 배지와 Windows/브라우저 알림이 기존 방식대로 발생하는지 확인한다.
9. 수신자가 답장했을 때 발신자와의 1:1 대화로 돌아오는지 확인한다.
