# 발주일 수정 적용 안내

1. 기존 v175(발주번호), v177(확정 취소), v180(자재 요청/권한) SQL이 적용된 DB에서 진행합니다.
2. Supabase SQL Editor에서 `v181_material_order_date_history.sql` 전체를 직접 실행합니다. 운영 DB에는 자동 실행하지 않았습니다.
3. 수정된 프론트 코드를 반영하고 화면을 새로고침합니다. 현재 작업에는 배포가 포함되지 않습니다.

## 적용 내용

- 신규 발주서는 발주일에 과거 날짜를 입력할 수 있습니다.
- 저장된 발주서는 ‘발주일 수정’으로 날짜를 즉시 저장합니다. 다른 편집 내용은 별도로 저장합니다.
- 작성중 문서는 발주 메뉴 권한으로 수정하며 날짜에 맞춰 발주번호를 다시 부여합니다.
- 확정/결재요청 문서와 확정 취소 이력이 있는 문서는 해당 현장 자재관리 권한과 수정 사유가 필요합니다. 발주번호와 품목/수량/상태는 유지합니다.
- 취소 상태는 날짜 수정을 차단합니다. 날짜 변경 이력이 있는 문서는 이력 보존을 위해 삭제할 수 없습니다.
- 최초 등록시각/등록자는 DB에서 보호하고 변경 전후 날짜, 수정자, 수정시각, 사유를 자동 기록합니다. 적용 이전의 변경 이력은 복원하지 않습니다.
- 입고 및 정산 마감 정보는 현재 발주서와 연결되어 있지 않습니다. 따라서 입고/마감 후 관리자만 허용하는 판정은 이번 기능에 포함되어 있지 않으며 해당 데이터 연결 후 추가해야 합니다.

## 적용 후 확인

테스트용 문서와 계정으로 다음을 확인하세요. 실제 운영 문서의 날짜를 테스트 목적으로 변경하지 마세요.

| 확인 | 예상 결과 |
|---|---|
| 작성중 발주일을 지난달로 변경 | 지난달 목록으로 이동, 번호 갱신, 변경 이력 1건 추가 |
| 수정 후 품목을 일반 저장 | 변경한 날짜/번호/이력/최초 등록시각 유지 |
| 일반 발주 담당자가 확정 문서 조회 | 발주일 수정 버튼 없음, 직접 API 요청도 거부 |
| 자재관리 담당자가 확정 문서를 사유 없이 수정 | 저장 거부 |
| 자재관리 담당자가 사유와 함께 수정 | 날짜만 변경, 기존 번호/상태/수량 유지, 이력 추가 |
| 확정을 취소한 뒤 날짜 수정 | 관리자 권한과 사유 요구 유지 |
| 접근 권한 없는 현장의 ID로 API 요청 | 수정 거부 |
| 이력/등록시각/등록자 직접 UPDATE | 변경 거부 |
| 두 화면에서 같은 문서를 열고 차례로 날짜 수정 | 늦게 요청한 화면에 새로 열기 안내 |
| 날짜 변경 이력이 있는 문서 삭제 요청 | 삭제 거부 |

로컬 PostgreSQL 실행 환경이 없어 SQL 실행 검증은 수행하지 못했습니다. 프론트 빌드와 lint 비교는 별도로 수행했습니다.
