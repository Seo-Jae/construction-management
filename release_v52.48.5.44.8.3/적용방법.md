# v52.48.5.44.8.3 적용방법

1. ZIP을 현재 프로젝트 루트(`package.json`, `src` 폴더가 있는 위치)에 풉니다.
2. PowerShell에서 아래 명령을 실행합니다.

```powershell
node release_v52.48.5.44.8.3/apply-v52.48.5.44.8.3-contract-item-semantic-dedupe.cjs
npm run build
git add .
git commit -m "fix: contract item semantic duplicates v52.48.5.44.8.3"
git push
```

3. Supabase SQL Editor에서 아래 파일을 전체 실행합니다.

```text
supabase/v52.48.5.44.8.3_contract_item_semantic_dedupe.sql
```

4. 마지막 결과가 아래처럼 나오는지 확인합니다.

```text
contract_item_count = 91
distinct_source_key_count = 91
semantic_item_count = 91
remaining_semantic_duplicate_rows = 0
new_contract_item_count = 91
backup_row_count = 91
```

5. 사이트에서 F5 후 `기성관리 > 계약품목 공정연결`의 전체 품목이 91개인지 확인합니다.

## 안전장치

- SQL은 진단 당시 계약버전 ID와 `182 / 91 / 91` 구조를 다시 검증합니다.
- 데이터가 달라졌다면 예외를 발생시키고 전체 트랜잭션을 되돌립니다.
- 삭제 대상 91행은 `progress_contract_items_dedupe_backup`에 JSON으로 백업합니다.
- 다른 현장과 다른 계약버전은 정리 대상에 포함되지 않습니다.
