# 사내시스템 v52.00 적용방법

이번 패키지는 **회원권한 2~5단계를 한 번에 적용**합니다. v51.99 SQL에서 발생한 `project_name is ambiguous` 오류도 수정되어 있으므로, 기존 v51.99 SQL은 다시 실행하지 않습니다.

## 1. Supabase 통합 SQL 실행

Supabase 프로젝트의 `SQL Editor`에서 아래 파일 전체를 붙여넣고 실행합니다.

```text
Supabase에서_실행_회원권한_2~5단계_통합_v52.00.sql
```

v51.99 실행이 오류로 롤백된 상태에서도 이 파일 하나만 실행하면 됩니다. 테이블과 기준정보는 `if not exists` 및 `on conflict` 방식으로 구성해 재실행할 수 있습니다.

## 2. 코드 적용

프로젝트 최상위 폴더에서 PowerShell을 열고 아래 명령을 실행합니다.

```powershell
node .\release_v52.00\apply-v52.00-permission-phase2-to5.cjs
npm run build
```

적용 스크립트는 교체 대상 파일을 `backup_v52.00_날짜시간` 폴더에 자동 백업합니다.

## 3. 확인 순서

1. 최고관리자 계정으로 `회원관리`를 엽니다.
2. 기존 회원이 자동 변환되어 목록과 상세설정에 표시되는지 확인합니다.
3. 회원 한 명을 선택하고 부서·권한 템플릿·접근현장을 저장합니다.
4. 세부권한에서 `상속 / 추가 / 차단`을 각각 설정하고 저장합니다.
5. `모든 접근현장 공통`과 개별 현장 범위를 바꿔 예외권한을 저장합니다.
6. 특수권한을 한 개 켜고 저장한 뒤 새로고침 후 유지되는지 확인합니다.
7. 권한 변경이력에 변경일시·변경자·변경내용이 표시되는지 확인합니다.
8. 승인대기 계정의 `승인 후 사용 시작`, 사용중 계정의 `사용중지`가 기존처럼 작동하는지 확인합니다.
9. 노임·자재 화면의 시작월·종료월이 `2026년 8월` 형식인지 확인합니다.

## 현재 적용 범위

- 회원별 세부권한·현장별 예외 저장 및 재조회: 적용
- 특수권한 저장 및 재조회: 적용
- 기존 회원 자동 변환: 적용
- 권한 변경이력 기록 및 화면 조회: 적용
- 기존 승인·거절·사용중지·복수현장 저장: 유지
- 사이드바 메뉴 숨김과 각 화면 버튼·DB 동작 차단: 다음 연결 단계
