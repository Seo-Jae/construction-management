# v52.48.5.44.68 변경내용

## 1. 주간업무총괄 > 현장 설정 동적화
- 기존 소스에 고정되어 있던 9개 현장명을 기본 현장 목록으로 사용하지 않습니다.
- `admin_list_projects_v1`에서 현재 시스템에 등록된 현장 목록을 불러와 기본 선택합니다.
- 새로 등록한 Test현장 등도 주간업무총괄에서 자동으로 후보에 포함됩니다.
- 주간업무 완료 자료 조회 시 기존 고정 현장명 `.in(...)` 필터를 제거하여 해당 주차의 완료 보고서를 전체 조회합니다.
- 등록 현장이 양식 슬롯보다 많을 때는 최신 주간업무 완료 자료가 있는 현장을 우선 배치해 새 Test현장 등의 보고가 누락되지 않도록 합니다.
- `현장 설정` 버튼을 추가했습니다.
  - 시스템 등록 현장: 기본 체크
  - 필요 없는 현장: 체크 해제 가능
  - 시스템에 없는 종료/하자 현장: `이번 주 수동 현장`으로 직접 추가 가능
- 수동 현장은 해당 주차의 총괄 저장 payload에만 저장되므로 시스템 현장 목록에는 추가되지 않습니다.
- 현재 주간업무총괄 Excel 원본 양식의 현장 슬롯이 9개이므로 화면/Excel에 최대 9개 현장을 표시합니다.
- 9개를 초과하면 수동 추가 현장과 해당 주차 주간업무가 등록된 현장을 우선 표시하고 경고를 보여줍니다.
- 현장 설정을 변경해도 동일 현장의 기존 직접입력 내용은 현장명을 기준으로 가능한 범위에서 유지합니다.
- XLS 생성 시 B6, B10 ... B38 현장명도 현재 현장 설정에 맞게 자동 교체합니다.

## 2. 주간업무보고 > 결재완료 후 수정
- 담당자 본인이 작성한 주간업무보고는 `결재 완료` 상태라도 수정 아이콘을 사용할 수 있습니다.
- 결재완료 보고서를 수정 저장하면 상태를 `작성중(draft)`으로 되돌리고 `재결재요청`이 필요하다는 안내를 표시합니다.
- 기존에 주간업무총괄에 반영되어 있던 완료본은 재결재 전까지 그대로 유지됩니다.
- 수정 후 `재결재요청`을 누르면 기존 `complete_weekly_report_direct` 흐름으로 다시 결재완료 처리되고, `weekly_reports`의 최신 payload가 주간업무총괄에 반영됩니다.

## 3. Supabase SQL
- `save_weekly_report_revision_draft(...)` RPC를 추가합니다.
- 본인이 작성한 `weekly` 보고서만 수정본으로 저장할 수 있도록 `auth.uid()`를 검증합니다.
