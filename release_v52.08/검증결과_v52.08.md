- 실제 Supabase 프로젝트에 SQL 실행
- 실제 Storage 업로드/다운로드
- 실제 Supabase Realtime 2계정 송수신
- 실제 브라우저 반응형 화면 조작
- v52.08 `npm run build`

사용자가 보낸 프로젝트 ZIP에는 `node_modules`가 포함되지 않았기 때문에 이 작업 환경에서는 Vite production build를 직접 실행하지 않았다.

따라서 현재 상태는 **개발파일 완성(C) / 사용자 환경 통합검증 전**으로 본다.

## 보안 검토

- service role key를 프런트에 추가하지 않음
- 메신저 테이블 직접 insert/update/delete 권한을 authenticated에서 제거하고 RPC 사용
- 대화방 참여 여부를 DB RPC에서 재검증
- 조회 RLS는 대화방 참여자 기준
- Storage bucket은 private
- Storage 조회는 방 참여자 기준
- Storage 업로드 경로는 `<room_id>/<auth.uid()>/...` 규칙 강제
- Storage 삭제는 owner_id가 현재 사용자와 같은 경우만 허용
- 계정 삭제 시 메시지 작성자 FK는 `SET NULL`로 두고 이름/직급/현장 snapshot은 메시지에 보존
