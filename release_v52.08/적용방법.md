# v52.08 메신저 v1.2 적용방법

## 전제

현재 프로젝트가 v52.07 누적 파일을 적용한 상태여야 한다.

v52.07이 아직 Git/Vercel Production까지 올라가지 않았더라도, 로컬 파일에 v52.07이 적용되어 있고 `npm run build`가 성공한 상태라면 v52.08 개발 테스트를 이어갈 수 있다.

---

## 1. Supabase SQL 먼저 실행

Supabase Dashboard → SQL Editor에서 아래 파일을 처음부터 끝까지 실행한다.

```text
release_v52.08\Supabase에서_실행\00_메신저_v1.2_전체설치.sql
```

SQL 마지막 확인 결과에서 다음 4개 테이블명이 null이 아니어야 한다.

```text
messenger_rooms
messenger_room_members
messenger_messages
messenger_attachments
```

그리고 Storage bucket 조회 결과에 다음 행이 보여야 한다.

```text
messenger-files / public=false / file_size_limit=10485760
```

---

## 2. 프로그램 파일 적용

ZIP을 현재 프로젝트의 `package.json`과 `src`가 보이는 최상위 폴더에 풀고 PowerShell에서 실행한다.

```powershell
node .\release_v52.08\apply-v52.08-messenger-v1.2.cjs
```

자동 적용 파일:

```text
src/Dashboard.jsx
src/components/MessengerButton.jsx
src/page/Messenger.jsx
src/utils/messengerFiles.js
```

기존 파일은 `backup_v52.08_날짜시간` 폴더에 자동 백업된다.

---

## 3. 빌드

```powershell
npm run build
```

마지막에 `built in ...`가 나오면 빌드 성공이다.

---

## 4. 실제 기능 테스트

가능하면 서로 다른 로그인 계정 A/B를 브라우저 2개 또는 일반창/시크릿창에 각각 로그인해서 확인한다.

1. A에서 상단 메신저 아이콘 클릭
2. B와 1:1 대화방 생성
3. A → B 텍스트 전송
4. B 화면에 실시간 반영 확인
5. B가 다른 화면에 있을 때 상단 메신저 배지 증가 확인
6. B가 대화방을 열었을 때 읽지않음 감소 확인
7. 사진 전송 및 미리보기 확인
8. PDF/Excel 등 일반 파일 전송 및 다운로드 확인
9. 그룹방 생성
10. 그룹명 변경
11. 참여자 추가/제외
12. 본인이 보낸 텍스트/사진/파일 메시지 삭제 확인
13. 다른 사용자의 메시지에는 삭제 기능이 없는지 확인
14. 현장이 다른 사용자끼리도 대화 가능한지 확인
15. 참여하지 않은 방의 DB/Storage 데이터가 RLS로 노출되지 않는지 확인

---

## 5. Git 반영

실제 테스트까지 정상인 경우에만 진행한다.

```powershell
git status
git add src/Dashboard.jsx
git add src/components/MessengerButton.jsx
git add src/page/Messenger.jsx
git add src/utils/messengerFiles.js
git status
git commit -m "v52.08 add messenger v1.2"
git push origin main
```

`git add .`은 사용하지 않는다.

---

## 6. Production 확인

Vercel의 운영 프로젝트에서 새 Production 배포가 `Ready`가 된 뒤 실제 운영 주소에서 다시 2계정 송수신을 확인한다.

사용자가 Production 동작을 확인하기 전에는 배포 완료 상태로 보지 않는다.
