# v52.10 적용방법

## 중요
이전에 Supabase SQL Editor에서 v52.09 SQL이 아직 `Running...` 상태라면 먼저 해당 실행을 중지/취소한 뒤 진행한다.

v52.10 SQL은 기존 `messenger_leave_room(uuid)` 함수를 DROP하지 않는 안전 적용본이며, lock timeout 5초와 statement timeout 60초를 설정해 무한 대기를 피하도록 했다.

## 1. Supabase
SQL Editor에서 아래 파일 전체를 실행한다.

`release_v52.10/Supabase에서_실행/00_v52.10_메신저_사용성_안전적용.sql`

마지막 확인 SELECT에서 다음 객체가 확인되면 된다.
- `messenger_user_preferences`
- `messenger_get_preferences()`
- `messenger_set_font_scale(numeric)`
- `messenger_transfer_owner(uuid,uuid)`
- `messenger_leave_room(uuid,uuid)`

## 2. 프로그램 적용
ZIP을 `package.json`이 있는 프로젝트 최상위에 압축 해제한다.

PowerShell:

```powershell
node .\release_v52.10\apply-v52.10-messenger-web-window.cjs
npm run build
```

마지막에 `✓ built in ...`이 나오면 로컬 빌드 성공이다.

## 3. 브라우저 알림 권한
ERP 상단 메신저 아이콘을 한 번 클릭하면 브라우저가 알림 권한을 요청할 수 있다.
`허용`을 선택해야 Windows/브라우저 시스템 알림이 표시된다.

이번 1차 버전은 별도 EXE/PWA 설치가 필요 없다. 단, 브라우저를 완전히 종료한 상태까지 알림을 받는 Push 기능은 포함하지 않는다.

## 4. 우선 테스트
1. 기성/일보 등 작성 화면에서 값을 입력하고 메신저 클릭
2. ERP 업무화면이 그대로 남아 있는지 확인
3. 메신저가 별도창으로 열리는지 확인
4. 메신저에 전송하지 않은 문장을 입력
5. ERP 또는 다른 프로그램으로 이동
6. 다시 메신저 버튼 클릭 → 메신저 창이 새로고침되지 않고 그대로 앞으로 오는지 확인
7. 메신저 창을 닫았다 다시 열기 → 마지막 대화방/작성 중 텍스트 복원 확인
8. 다른 사용자에게 메시지를 보내도록 요청 → Windows 우측하단 시스템 알림 확인
9. 알림 클릭 → 해당 대화방으로 이동 확인
10. 대화창 배경색 확인
11. 기존 글자크기/방장위임/Ctrl+V/첨부/읽음 기능 회귀 테스트
