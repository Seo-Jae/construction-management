# v52.34 변경내용

## 목적
근로자 마스터에 실제 노임작성/근로계약서에서 반복 사용하는 개인정보를 저장하되 평문 DB를 만들지 않습니다.

## 저장 보호정보
암호화 payload:
- 주민등록번호
- 외국인등록번호
- 전체 휴대폰번호
- 주소
- 국적
- 은행
- 계좌번호
- 예금주

## 평문으로 남기는 최소 파생값
검색/업무 식별을 위해 근로자 마스터에는 아래만 유지합니다.
- 생년월일
- 휴대폰 뒤 4자리
- 계좌 뒤 4자리
- 은행명 힌트
- 각 보호정보 등록여부

주민번호 전체, 전체 전화번호, 주소, 계좌번호 전체는 평문 컬럼으로 만들지 않습니다.

## 암호화
- Supabase Vault에 데이터 암호화 키 저장
- DB에는 암호문 `bytea`만 저장
- 암호화키가 없으면 SQL 적용 시 1회 자동생성
- Vault decrypted view를 anon/authenticated/public에서 직접 읽지 못하도록 차단
- 보호정보 테이블 RLS 활성화 + 직접 권한 revoke

## 관리화면
- 기존 원문 조회 기능 없음
- 기존값은 마스크/등록여부만 표시
- 수정할 때 새 값을 입력한 항목만 암호화 payload에 덮어씀
- 빈칸은 기존 보호정보 유지
- 기본정보 + 보호정보는 단일 RPC 호출 안에서 저장

## 감사기록
보호정보 변경 감사로그에는 원문을 남기지 않습니다.
`changed_fields`만 저장합니다.

예:
- phone_number
- account_number
- address
