# v52.34 적용방법

## 1. Supabase SQL 먼저 실행

Supabase SQL Editor에서 아래 파일 전체를 실행합니다.

`release_v52.34/Supabase에서_실행/00_v52.34_근로자보호정보_Vault암호화.sql`

이 SQL은:
- `pgcrypto` 사용
- Supabase Vault 사용
- Vault에 `labor_pii_data_key_v52_34` 암호화키 1회 생성
- `labor_worker_private` 암호문 테이블 생성
- 직접 테이블 접근 차단
- v52.34 관리목록/보호정보 저장 RPC 생성

을 수행합니다.

## 2. 프로그램 적용

프로젝트 최상위에서:

```powershell
node .\release_v52.34\apply-v52.34-worker-private-encryption.cjs
npm run build
```

## 3. Git

빌드 성공 후:

```powershell
git add src/page/WorkerMasterManagement.jsx
git status
git commit -m "v52.34 encrypt labor worker private data"
git push origin main
```

`git add .`은 사용하지 않습니다.

## 4. 화면 확인

`노임관리 > 근로자 정보관리 > 근로자 등록/수정`

보호정보:
- 주민등록번호
- 외국인등록번호
- 전체 휴대폰번호
- 주소
- 국적
- 은행
- 계좌번호
- 예금주

기존 보호정보가 이미 있으면 원문은 화면에 다시 나타나지 않습니다.
빈칸은 기존 암호화 값 유지이며, 변경할 항목만 새 값을 입력합니다.

목록에는:
- 주민번호 등록 여부
- 연락처 등록 여부
- 주소 등록 여부
- 계좌 등록 여부
- 계좌 뒤 4자리
등의 안전한 상태만 표시합니다.

## 5. 아직 하지 않는 기능

이번 v52.34에서는 아래는 아직 하지 않습니다.
- 민감정보 원문 조회 버튼
- 노임 Excel 생성
- Excel 다운로드
- SMS 인증
- 다운로드 감사로그

원문 복호화는 다음 단계의 `SMS 인증 완료된 특정 현장/특정 월 Excel 생성` 업무 흐름에서만 연결합니다.
