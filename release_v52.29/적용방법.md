# v52.29 적용방법

## 결론
기존 2025-07 ~ 2026-05 출력일보를 다시 업로드하지 않습니다.
이미 DB에 들어간 자료의 `workers[].job`만 안전하게 보정합니다.

## 1. Supabase SQL 먼저

Supabase SQL Editor에서 다음 파일 전체를 실행합니다.

```text
release_v52.29\Supabase에서_실행\00_v52.29_용인금어지구_과거일보_job정규화.sql
```

SQL은 수정 전에 해당 현장/기간의 `workers` 전체를
`daily_reports_workers_backup_v52_29` 테이블에 먼저 백업합니다.

변경 대상:
- 먹메김 → 먹매김
- 경량 → 경량벽체
- 경량골조 → 경량벽체
- 경량석고 → 경량벽체
- 천정 → 세대천정

`process`, 이름, 위치, 작업내용 등은 수정하지 않습니다.

SQL 마지막 조회 결과에서 아래 구형 job은 없어야 합니다.
- 먹메김
- 경량
- 경량골조
- 경량석고
- 천정

## 2. 프로그램 적용

프로젝트 최상위에서:

```powershell
node .\release_v52.29\apply-v52.29-daily-report-cumulative-normalization.cjs
```

정상 메시지:

```text
[v52.29 적용 완료]
```

그 다음:

```powershell
npm run build
```

## 3. Git

실제 프론트 변경 파일은 2개입니다.

```powershell
git add src/Dashboard.jsx
git add src/page/HistoricalDailyReportUpload.jsx
git status
git commit -m "v52.29 fix daily report cumulative and legacy jobs"
git push origin main
```

`git add .`은 사용하지 않습니다.

## 4. 확인

예를 들어 2026-08-12 출력일보를 다운로드하면 전일누계는
**2026-08-01 ~ 2026-08-11**만 합산되어야 합니다.
2025-07 ~ 2026-07 자료는 전일누계에 들어가면 안 됩니다.

또한 과거 일보를 새로 업로드하더라도 앞으로는 구형 job을 자동 정규화합니다.

## 롤백

DB 보정 결과에 문제가 있으면:

```text
release_v52.29\Supabase에서_실행\99_v52.29_롤백_원본workers복원.sql
```

을 실행하면 SQL 적용 전 workers 배열로 복원됩니다.
