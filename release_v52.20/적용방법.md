# v52.20 적용방법

## 목적
작업자 출·퇴근 앱에서 **명시적으로 로그아웃하지 않는 한 로그인 상태를 유지**합니다.

기존 구조는 프론트 토큰은 `localStorage`에 저장되지만 서버 세션이 30일 후 만료되고,
세션 확인 RPC가 일시적으로 실패해도 프론트가 토큰을 즉시 삭제하는 문제가 있었습니다.

## 1. Supabase SQL
Supabase SQL Editor에서 아래 파일 전체를 실행합니다.

`release_v52.20\Supabase에서_실행\00_v52.20_작업자앱_로그인상태유지.sql`

적용 효과:
- 기존 작업자 세션 `expires_at` → `infinity`
- 앞으로 생성되는 작업자 세션도 자동 만료 없음
- 기존 기기 바인딩 검증은 유지
- 기존 로그아웃 RPC가 세션 행을 DELETE하므로 직접 로그아웃하면 정상적으로 로그인 해제

## 2. 프론트 적용

프로젝트 최상위에서:

```powershell
node .\release_v52.20\apply-v52.20-worker-login-persistence.cjs
```

`[v52.20 적용 완료]` 확인 후:

```powershell
npm run build
```

## 3. Git

이번 프론트 변경 파일은 1개입니다.

```powershell
git add src/page/AttendanceWorkerPortal.jsx
git status
git commit -m "v52.20 persist attendance worker login"
git push origin main
```

`git add .`은 사용하지 않습니다.

## 4. 배포 후 테스트

1. 작업자 계정 로그인
2. 작업자 앱 완전히 종료
3. 다시 실행
4. 휴대폰 다른 앱 사용 후 복귀
5. 인터넷을 잠시 끊었다 다시 연결
6. 작업자 앱 재실행

→ 전화번호/비밀번호를 다시 요구하지 않고 기존 로그인 상태가 복원되어야 합니다.

추가 확인:
- 작업자가 직접 `로그아웃`하면 다음 실행 때 로그인 화면이 나와야 함
- 관리자에서 기기 변경/계정 삭제 등으로 실제 세션이 무효화된 경우에는 다시 로그인이 필요함
- 휴대폰에서 앱 데이터/브라우저 사이트 데이터를 사용자가 직접 삭제하면 localStorage도 삭제되므로 재로그인이 필요함
