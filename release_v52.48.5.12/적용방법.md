# v52.48.5.12 적용방법

적용 기준은 `v52.48.5.11`입니다.

## 1. Supabase SQL 먼저 실행

Supabase SQL Editor에서 아래 파일의 전체 내용을 실행합니다.

`Supabase에서_실행/00_v52.48.5.12_공동작업_통합승인_전체골구도.sql`

SQL 실행이 완료되기 전에 새 프론트엔드를 배포하면 신규 RPC 호출이 실패할 수 있습니다.

## 2. 코드 적용

프로젝트 최상위 폴더에서 압축을 해제한 뒤 PowerShell에서 실행합니다.

```powershell
node .\release_v52.48.5.12\apply-v52.48.5.12-shared-progress.cjs
npm run build
git add src/page/AttendanceManagement.jsx src/components/AttendanceProgressBuildingOverview.jsx
git status
git commit -m "v52.48.5.12 add shared progress approval"
git push origin main
```

적용 스크립트는 기존 파일이 정확히 `v52.48.5.11`인지 먼저 검사하고, 다르면 덮어쓰지 않습니다. 기존 파일을 교체할 때는 프로젝트 안에 백업 폴더를 자동 생성합니다. 이미 적용된 상태에서 다시 실행해도 파일을 중복 수정하지 않습니다.

## 3. 배포 후 확인

1. 같은 공정의 작업자 2명이 같은 세대를 포함하여 퇴근 진척을 제출합니다.
2. 통합관리시스템의 근태기록에서 제출이 공동작업 한 묶음으로 보이는지 확인합니다.
3. 상세 화면에서 해당 동 전체 골구도와 색상 구분을 확인합니다.
4. `통합 승인` 후 같은 세대가 진척도에 한 번만 반영되는지 확인합니다.
5. 이미 완료된 세대가 이후 작업자의 퇴근 화면에서 선택되지 않는지 확인합니다.
6. 테스트계정만 초기화했을 때 다른 공동작업자의 승인 진척이 유지되는지 확인합니다.

앱을 다시 설치할 필요는 없습니다. 배포 후 브라우저 새로고침 또는 앱 종료 후 재실행으로 새 화면을 불러오면 됩니다.
