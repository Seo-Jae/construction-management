# Dashboard 현장설명·입찰 과거 이력

- 현장설명·입찰 현황의 버튼명은 `삭제`입니다.
- 대상 행을 선택하고 `삭제`를 확인하면 즉시 저장하여 현재 목록에서 제외하고 과거 이력 등록 여부를 확인합니다. 삭제 후 별도 저장을 누를 필요는 없습니다.
- 새로 입력했거나 수정한 행은 먼저 저장해야 삭제할 수 있습니다. 미저장 수정 내용이 사라지는 것을 방지합니다.
- `과거 이력`에서 건설사·현장·공종·참석자·비고 검색과 현설/입찰 연도 필터를 사용할 수 있습니다.
- 회의 일정과 현재 캘린더의 기본 동작은 유지합니다. 보관된 현설/입찰은 현재 캘린더에서 제외됩니다.
- 조회 전용 사용자도 원본 Dashboard 보드를 조회할 권한이 있으면 같은 범위의 이력을 조회할 수 있습니다. 일반 사용자의 이력 직접 수정·삭제는 차단합니다.
- 이미 삭제된 자료는 이번 변경으로 복원되지 않습니다. 기능 적용 후 제거되는 저장 행부터 보존됩니다.

## DB 적용 상태

`supabase/v186_dashboard_schedule_history.sql`을 사용자 직접 실행용으로 제공했습니다. 현재 세션에서는 운영 DB 적용 여부를 직접 확인하지 못했습니다.
연결 복구 후 원본 테이블의 `site_schedules` 형식, 원본 RLS와 저장 RPC 권한, 이력 트리거 적용 여부를 확인해야 합니다.
SQL은 원본에서 빠지는 행을 같은 트랜잭션에서 자동 보관합니다. 이력 저장 실패 시 원본 저장도 실패하므로 이력만 누락되지 않습니다.
기존 클라이언트의 삭제 저장도 트리거로 보관합니다. 이력 테이블 준비 전 새 화면의 삭제 버튼은 비활성화합니다.
프론트는 기존 main 브랜치의 Vercel 자동 배포 경로를 사용합니다.
