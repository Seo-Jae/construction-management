# 공동 자재 검색어 1차 기능

## 적용 순서

1. Supabase SQL Editor에서 `supabase/v185_material_shared_aliases.sql` 전체를 실행합니다. 선행 v180이 필요합니다.
2. `supabase/v185_material_shared_aliases_verify.sql`로 테이블 보호 및 RPC 권한을 확인합니다.
3. 프론트 변경을 배포한 뒤 화면을 새로고침합니다.

사용자의 SQL 직접 실행 요청에 따라 v185를 연결된 운영 DB에 적용했습니다. 테이블 2개의 RLS·직접 접근 차단, RPC 5개의 실행 권한, 검색어 열 및 연결 트리거 활성화를 확인했습니다. 프론트는 이 변경을 main에 반영하여 기존 Vercel 자동 배포로 제공합니다.
SQL 적용 전에는 공동 검색어 기능이 활성화되지 않으며 기존 품명 검색·신규자재요청을 유지합니다.
기존 DB 자료를 삭제하거나 기존 마스터의 검색어를 덮어쓰지 않습니다.

## 담당자 사용법

- 발주 품명을 검색하면 기존 마스터의 품명·별칭과 공동 검색어를 함께 검색합니다.
- 공유 검색어로 찾은 결과에는 `담당자 추천 후보` 또는 `공통 검색어`가 표시됩니다.
- 선택한 품명 아래 `검색어 연결·검토 요청`에서 다른 검색어를 등록할 수 있습니다.
- 새로운 표현을 입력해 자재를 선택했을 때 연결 안내를 표시합니다. 단순한 품명의 일부를 입력한 경우에는 안내하지 않습니다. 같은 화면에서 건너뛴 같은 연결은 다시 안내하지 않습니다.
- 연결 전 선택한 품명·규격·단위를 확인합니다. 관련 소모품·대체품·상이한 규격을 같은 자재로 연결하지 않습니다.
- 연결된 검색어가 잘못되었으면 같은 팝업의 `연결이 맞지 않아요`로 신고합니다. 사용자당 같은 연결에 대한 신고는 한 번만 집계됩니다.
- 검색 결과가 없으면 기존 신규자재요청으로 진행합니다. 요청 품명을 수정해도 처음 검색어를 별도로 보관하며, 관리자가 마스터에 연결하면 해당 검색어를 추천 후보로 남깁니다. 표준 품명과 같은 검색어는 중복 등록하지 않습니다.

## 관리자 사용법

- 자재마스터의 `공동 검색어 검토`에서 현재 현장에서 등록한 후보·승인·해제 목록을 조회합니다.
- 검색어·품명·규격·공정 및 잘못된 연결 신고 수를 확인합니다.
- 최대 500개씩 선택하여 `선택 검색어 승인` 또는 `선택 연결 해제`를 실행합니다.
- 해제된 연결은 검색에서 제외되며 일반 담당자가 다시 등록하여 복구할 수 없습니다. 관리자만 재승인할 수 있습니다.
- 다른 현장에서 등록한 연결은 그 현장의 관리 권한으로 검토합니다. 여러 현장을 관리하는 사용자는 선택 현장을 바꾸어 검토합니다.

## 공유 및 권한

- 공유 검색 결과는 자재 ID, 검색어, 상태만 반환합니다. 등록 현장·사용자 정보, 발주 수량·단가·거래처는 반환하지 않습니다.
- 후보 테이블과 신고 테이블은 RLS를 활성화하고 일반 사용자의 직접 접근 권한을 차단합니다.
- 등록·신고는 선택 현장의 자재발주 또는 자재관리 권한이 필요합니다. 승인·해제는 등록 현장의 자재관리 권한이 필요합니다.
- RPC에서도 기존 v180의 사용자 상태·현장 범위·권한 예외 규칙을 검사합니다.
- 자재마스터는 기존 접근 정책을 따르며 신규 테이블에만 보호 규칙을 추가합니다.

## 검증

- `node --test tests/materialAliases.test.mjs`: 검색어 정규화, 후보/해제 분리, 기존 검색어 보존, 500개 초과 조회, 오류 전파, 실제 발주 검색 로더, SQL 미적용 호환성, 승인 후보 정렬 검증.
- `npx.cmd --no-install eslint src/components/MaterialAliasDialog.jsx src/utils/materialAliases.js`
- `npm.cmd run build`

SQL은 운영 DB에 적용 성공했으며 구조·권한 검증을 통과했습니다. 아래 로그인 사용자별 화면 흐름은 프론트 배포 후 확인해야 합니다.

1. 현장 A 담당자가 검색어를 연결하고 현장 B 담당자가 같은 검색어로 동일 자재를 찾는지 확인합니다.
2. 관리자가 후보를 승인한 후 공통 검색어 표시가 나오는지, 해제 후 새로고침하면 검색에서 제외되는지 확인합니다.
3. 일반 사용자의 승인 요청과 현장 A 관리자의 현장 B 검색어 승인 요청이 서버에서 거부되는지 확인합니다.
4. 신규 요청의 품명을 수정한 뒤 기존 자재 또는 새 자재로 연결했을 때 최초 검색어가 후보로 남는지 확인합니다.
5. 좁은 화면에서도 검색 목록·등록 팝업·검토 목록과 내부 스크롤이 정상인지 확인합니다.

## 이번 범위에 포함하지 않은 기능

AI 기반 유사어 추론, 관련 자재·대체품 추천, 발주확정 횟수에 따른 추천 점수 및 자동 승인은 포함하지 않습니다. 검색어나 품목 클릭만으로 연결을 자동 확정하지 않습니다.
