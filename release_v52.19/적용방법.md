# v52.19 적용방법

## 목적
이번 버전은 특정 메뉴 수정이 아니라 **사내 시스템 전체의 화면/작업상태 안정성**을 보완합니다.

### 수정 1 — 전체 업무화면 유지
- Chrome 다른 탭 이동 후 복귀
- Excel/CAD/기타 프로그램 사용 후 복귀
- Windows 작업표시줄에서 Chrome 최소화/복원
- Supabase 인증 토큰 자동갱신
- 30초 프로필 갱신
- 브라우저 focus 재획득

이 과정에서 Dashboard를 LoadingScreen으로 교체하지 않도록 합니다.

### 수정 2 — 공정 선택 이중 보호
공정진척관리에서 선택한 공정을 `sessionStorage`에도 저장합니다.
앱 내부 state는 그대로 유지되고, 실제 브라우저 새로고침이 발생해도 같은 탭에서는 선택 공정을 복원합니다.

### 수정 3 — 메신저 최근 메시지 위치
이미지 메시지는 DB에 저장된 가로/세로 크기로 표시공간을 **로드 전에 먼저 확보**합니다.
대화방 최초 진입 시 일정 시간 최신 메시지 위치를 고정하며,
사용자가 직접 위로 스크롤하면 자동고정은 즉시 해제합니다.

## SQL
**SQL 변경 없음**

## 적용

프로젝트 최상위에서:

```powershell
node .\release_v52.19\apply-v52.19-global-state-messenger-scroll.cjs
```

`[v52.19 적용 완료]` 확인 후:

```powershell
npm run build
```

빌드 마지막에 `✓ built in ...`가 나와야 합니다.

## Git
이번 실제 변경 파일은 3개입니다.

```powershell
git add src/App.jsx
git add src/Dashboard.jsx
git add src/page/Messenger.jsx
git status
git commit -m "v52.19 stabilize app state and messenger scroll"
git push origin main
```

`git add .`은 사용하지 않습니다.

## 배포 후 필수 테스트

### A. 전체 화면 유지
최고관리자와 일반 담당자 계정에서 각각:
1. 임의 업무 메뉴 진입
2. 입력란에 임시 내용 입력
3. Excel/CAD/다른 Chrome 탭으로 이동
4. Windows 작업표시줄에서 Chrome 최소화/복원
5. 다시 시스템으로 돌아오기

**현재 메뉴와 입력 중 내용이 그대로 남아 있어야 합니다.**

### B. 공정진척관리
1. `바닥먹`이 아닌 공정 선택
2. 다른 프로그램으로 이동
3. 복귀
4. 선택했던 공정 그대로인지 확인
5. F5 1회 후에도 같은 탭에서는 선택 공정이 복원되는지 확인

### C. 메신저
1. 사진이 포함된 대화방 선택
2. 최신 메시지가 사진보다 아래에 존재하도록 테스트
3. 대화방을 나갔다 다시 선택
4. 화면이 항상 최신 메시지 끝에 맞춰지는지 확인
5. 위로 직접 스크롤하면 자동으로 다시 아래로 끌려가지 않는지 확인
